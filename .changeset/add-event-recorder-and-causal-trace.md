Add `EventRecorder`, `createEventRecorder`, `CausalTraceEntry`, `FiredFault`, `EventRecorderOwnerIdentity`, `EventListenerSource`, `OPERATIVE_EVENT_TYPES`, `COMBINED_OPERATIVE_EVENT_TYPES`, and `CombinedOperativeEventClassMap` (AB-92, delivered by AB-255).

`@lostgradient/operative/test` exports `createEventRecorder(runtime: RuntimeServices): EventRecorder`, a deterministic event recorder built on top of a resource's complete event-map type rather than a hand-maintained name list. `EventRecorder.attach(source, ownerIdentity, eventTypes?)` subscribes through the public `addEventListener` surface (`ActiveRun`, or any `TypedEventTarget`-shaped source); `eventTypes` defaults to `COMBINED_OPERATIVE_EVENT_TYPES` — a frozen, runtime-visible array of every `CombinedOperativeEventType`, exhaustiveness-checked at compile time against `CombinedOperativeEventClassMap` — but a caller observing a different event map (a local test-only map, an armorer toolbox) can supply its own key list. `EventRecorder.attachIterable(source, ownerIdentity)` covers the second public run-handle shape (`AgentRun`/`DiagnosticAgentRun`, `AsyncIterable<RunEvent>`), tracking its consumption loop on `RuntimeServices.deferred` so a leaked iteration surfaces in a `deferred.drain()` report instead of hanging silently.

`EventRecorder.normalize()` returns every captured event as a `CausalTraceEntry`: timestamps are expressed only as an offset from the recorder's own `RuntimeServices.clock` origin, never an absolute wall-clock value, and identifier-shaped strings (UUIDs and `RuntimeIdentifiers.next(kind)` values alike) are rewritten to first-seen logical positions (`identifier-1`, `identifier-2`, ...) — two independently constructed manual runtimes running the same scripted case produce byte-identical `JSON.stringify(normalize())` output. `EventRecorder.assertSequence(expected)` asserts an exact ordered sequence for a single resource with no concurrent children. `EventRecorder.assertHappensBefore(before, after)` asserts a partial-order edge through `CausalTraceEntry.causedBy`, holding under either interleaving of two concurrent children.

`packages/operative/src/events.ts` also exports `OPERATIVE_EVENT_TYPES: readonly OperativeEventType[]`, each paired with a type-level exhaustiveness check that fails `check-types` when a member is added to the underlying event-class map without a matching array entry — the mechanism that makes "no hand-maintained allowlist" true rather than aspirational.

`createRunRecorder` (previously exported, unchanged shape: `{ events, steps, clear }`) is reimplemented on top of `createEventRecorder`: its hard-coded 32-entry `eventTypes` array — which silently omitted the `tool.*` bubble events, several session verbs, every schedule-lifecycle event, and the `toolbox.*`/`conversation.*` forwarded firehose — is deleted, replaced by `COMBINED_OPERATIVE_EVENT_TYPES`. `createRunRecorder` also gains an optional second parameter, `runtime?: RuntimeServices`, defaulting to `createDefaultRuntimeServices()`; existing call sites that omit it are unaffected. `RunRecorder.events`'s element type widens from `OperativeEventType`/`OperativeEventMap[...]` to `CombinedOperativeEventType`/`CombinedOperativeEventMap[...]`, reflecting the fuller capture set — a strict superset, so every existing `.type ===` comparison still type-checks.

Out of scope for this change: the fault engine and barriers (AB-95's `FaultPlan`/`FaultBoundary` vocabulary — `CausalTraceEntry.faultEvidence: FiredFault` is typed and ready, never populated by this slice), the reproduction-artifact writer, and Bureau-level recording.
