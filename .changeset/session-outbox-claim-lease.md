Add a claim lease to `SessionStore.outbox` (AB-390), closing the AB-389 residual where two processes sharing one persistent backend could both replay the same unacknowledged commit-outbox entry.

`outbox.claim(ordinal, { owner, until })` takes exclusive replay rights on one entry via a compare-and-swap on the entry's own new `claim` field (`SessionOutboxClaim`, `{ owner, until }`) — never a separate lock record. It resolves a `SessionOutboxClaimAttempt`: `{ claimed: true }` when the entry was unclaimed, its prior claim's `until` had already passed by this store's own `RuntimeServices.clock.now()`, or `owner` already held it (claim renewal always succeeds, and can only ever extend the stored `until`, never shorten it); `{ claimed: false, lease }` when a different, still-unexpired owner holds it (or a concurrent same-owner renewal already won — `lease` names the current winning claim either way, so a caller has fresh evidence to schedule a retry against); or `{ claimed: false }` with no `lease` when the entry no longer exists at all.

`outbox.acknowledge(ordinal, owner)` now takes the claiming `owner` as a required second argument and only removes the entry when `owner` still holds its claim (verified by the same compare-and-swap discipline, retrying against a fresh read when the CAS loses to this same owner's own concurrent renewal), returning `true` when the entry is gone after the call (removed by this call, or already gone) and `false` when a different owner reclaimed it first. This is a breaking change to `SessionStore.outbox.claim`/`acknowledge`'s signatures for any caller-supplied `SessionStore` implementation or direct caller of the built-in one; `pending()`'s signature is unchanged.

A drainer that crashes between winning a claim and acknowledging leaves the entry claimed but undelivered only until its own lease's `until` passes — a later drain (the same process's next tick, or a peer's) reclaims and completes it. This is at-least-once, not exactly-once: a crash after dispatch (or after the durable write persists) but before acknowledging still redelivers the entry once the lease expires, closing the gap where `audit-trail.ts`'s `session.deleted` listener and a direct `bureau.addEventListener('session.deleted', ...)` consumer could each observe a replay twice CONCURRENTLY — every consumer must still be idempotent on the entry's own `ordinal` for the crash-then-redeliver case.
