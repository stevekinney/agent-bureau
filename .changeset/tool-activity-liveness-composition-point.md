Adds AB-218's (obs-05) tool-call activity-liveness composition point, `packages/operative/src/durable/tool-activity-liveness.ts`, re-exported from `@lostgradient/operative/durable`: `selectToolCallClockSource(activityContext)` returns `'wall-clock-owner'` iff the current tool-call dispatch carries a Weft `ActivityContext` with a defined `activityAttemptToken`, `'monotonic-observer'` otherwise — selected once per invocation, never guessed from tool name or configuration. `createToolCallLivenessWatchdog(activityContext, clock, options?)` builds the matching `StallPolicy`-driven watchdog, reusing `WEFT_ACTIVITY_POLICY` verbatim for the activity branch (never a competing local timer, per AB-88's wall-clock-owner rule) and today's `toolCallPolicy` for the non-activity branch. `recordToolCallProgress(activityContext, watchdog, attempt, update)` forwards a tool's `progress({ checkpoint })` call to `ActivityContext.heartbeat(details)` (`details` is the checkpoint when present, otherwise the whole `{ percent, message, checkpoint }` update) when activity-backed, and records the same forwarded value as `'task-attempt-heartbeat'` evidence on the local watchdog; a non-activity tool call's `progress()` calls are never forwarded to Weft and are recorded as `'tool-progress'` evidence instead, matching today's behavior.

Tool execution is not wired to run as a Weft activity anywhere in this repository yet (`create-run-engine.ts`'s own documented behavior: "Tool execution is NOT an activity — it runs in-process inside `runStep`"); this is the composition point a future durable-activity dispatch path uses once one exists, and both branches are fully covered regardless.
